# PicShot

PicShot 是一个面向 Windows 的截图与图片工作台。磁盘图片只记录原文件路径，不自动复制图片。

当前正式版本：**v1.1.1**。本次修复更新检查与通知，并整合手动固定图片、袜夹外观等改进，详见 [完整更新说明](releases/v1.1.1.md)。

下载发布页中的 `PicShot-1.1.1-windows-x64.zip`，解压后运行 `app\PicShot.exe`。设置入口在屏幕最左侧钉子的右键菜单中；右侧袜夹继续用于打开图片收纳，图片自身的右键操作保持不变。

- 修复点击截图后选区窗口变黑：先获取当前屏幕的内存快照，再显示选区遮罩，并从未叠加遮罩的快照裁剪原图，不把遮罩和选区边框截入结果。选区坐标按实际画布与像素尺寸换算，支持反向拖选及边缘裁剪；Esc 或右键可取消。截图失败会提示并恢复截图绳，不自动将快照保存到磁盘。本修复尚未包含在 v1.1.1 发布包中。
- 修复一次截屏出现两张记录：优先读取剪贴板原始 PNG，按像素内容关联 30 秒内的自动收集记录，重复通知不延长关联窗口；剪贴板位图与新发现的原文件一致时，仅保留原文件路径，并沿用临时图片的手动分类。不合并两个不同路径的文件，不用手动导入覆盖临时记录，也不拦截用户主动进行的多次程序内截图；只在内存中计算指纹，不保存图片副本。像素或透明度不一致时保守保留，不使用模糊匹配。本修复尚未包含在 v1.1.1 发布包中。

## v1.1.1 更新

- 已移除桌面置顶参考图窗口，改为手动固定在截图绳上。
- 在袜夹或绳上右键图片，选择“固定在绳上”，即可保持悬挂，不再受目录和七天期限限制；手动固定的图片优先显示。点击照片夹也可固定，已经固定时再次点击会取消固定并收回袜夹。
- “收回袜夹”只改变分类，不移动或删除原文件。选择“恢复自动分类”可重新使用原来的目录与七天规则。
- 磁盘图片的手动分类仅作为状态记录保存，重启后恢复，仍只读取原路径、不创建图片副本；原文件不可用时仍不显示。临时截图的内容和分类只保留到程序退出。
- 修复检查更新失败：GitHub API 限流、超时或不可用时，自动改查同一仓库的官方发布页。发现新版本后仍校验对应安装包的 SHA-256 和大小，不跳过安全校验；手动检查与启动检查重叠时也会显示结果。
- 更新检查由启动时一次改为启动约 5 秒后首次检查，成功后每 4 小时再次检查；失败后依次等待 1、5、15、60 分钟，之后每 60 分钟重试。自动检查失败不弹窗打扰，手动检查仍显示结果。同一版本每次运行只自动提醒一次，关闭提示后仍可手动再次打开，重启后也会重新提醒；退出程序会取消未完成的检查。
- 重新绘制袜夹收纳入口，并统一钉子、绳索和悬挂配件的外观。
- 修正盘符根目录安装时的更新目标解析，以及成功启动后缓存清理失败误触发回滚的问题。

## 解决的问题

- 图片可以从任意文件夹导入，不依赖 Windows 的 Screenshots 文件夹。
- 添加文件夹后会持续监听新图片；原文件不可用时，图片会从截图绳上隐藏，原路径恢复后可以重新显示。
- 导入图片、监听文件夹和剪贴板文件列表只引用原文件，不创建本地副本。移动或删除原文件后，PicShot 不会从旧副本继续读取。
- `%LocalAppData%\FrameDock\data\state.json` 保存原文件路径、监听目录等记录，不保存图片内容。原文件仍可访问时，重启后才会恢复显示。
- 程序内截图和剪贴板位图只保存在运行时内存中，不自动写入图片文件；关闭程序后不会恢复。需要长期保留时，请主动使用“保存副本”并选择位置。
- 从绳上右键菜单正常退出会先保存路径记录；若保存失败，会提示并允许取消退出。强制结束进程无法保证本次新增路径记录保存成功。
- 截图绳显示最近 7 天内新出现或更新的截图目录根层图片、下载目录图片，以及本次运行的临时截图；这些图片超过 7 天后自动进入右侧袜夹。截图目录内的子文件夹图片和其他目录的图片不受 7 天等待期限制，直接按原文件夹归入袜夹。绳上图片多时可用鼠标滚轮横向浏览，不因数量多而提前归档。袜夹按原文件夹分类并可搜索、继续浏览，不会移动或复制原图；临时截图即使进入袜夹，关闭程序后仍会消失。截图目录会监听子目录，下载目录由系统定位并监听顶层文件；其他目录可手动添加监听。

## 构建和运行

需要 Windows 10/11 与 .NET Framework 4.8：

```powershell
.\build.ps1
.\build\PicShot.exe
```

仓库现在包含可直接运行的 `build\PicShot.exe` 及其 `.NET Framework 4.8` 配置文件。克隆仓库后可以直接执行 `.\build\PicShot.exe`；修改源码后再执行 `.\build.ps1` 重新生成该文件。其他构建产物、测试截图和本地运行数据不会提交。程序启动后会在屏幕顶部显示一条收起的截图栏。鼠标移到屏幕顶部时展开，鼠标离开后自动收起；单击图片复制，拖拽图片到其他程序取用，点击照片夹可以固定或取消固定在绳上。最右侧的袜夹打开按目录分组的收纳面板，单击图片复制、拖拽取用、右键可固定在绳上或打开原文件。绳上图片右上角的“×”及收纳面板的删除操作都会删除对应原文件（临时截图只移除）；删除原文件前会显示路径并要求确认，失败时保留图片记录。旧版自动创建的副本不再作为原文件的回退来源；旧版剪贴板图片可能以 `library` 内的文件作为原件，仍会按已有路径显示，删除该图片也会删除此文件。旧 `library` 文件不会自动清理，以免误删唯一的图片。从旧版升级时，若状态中仍有副本路径，会先校验并保留 `state.json.legacy` 元数据快照；旧状态有变化时保留带时间戳的新快照。无法完成备份则停止启动，避免覆盖旧路径记录。快照不含图片内容。

### 发布和自动更新

版本号由 `build.ps1 -Version` 注入，默认是 `1.1.1`。发布前更新默认版本、可执行文件和 `releases/<标签>.md` 更新说明，再创建符合 `v1.2.3` 格式的 Git 标签：

```powershell
$version = '1.1.2' # 示例：仅在准备发布该版本时使用
git tag -a "v$version" -m "Release PicShot $version"
git push origin "v$version"
```

GitHub Actions 会根据标签构建并发布对应版本的 ZIP，并使用仓库内的中文更新说明。上面的标签命令仅展示格式；下一次发布必须使用比现有正式版本更高的新版本号，并同步更新版本、说明文件和标签，不能重复创建或移动已发布标签。普通 `git push` 只更新源码，不生成新正式版本，也不会让旧客户端收到更新通知。

v1.1.1 会在启动后约 5 秒首次检查 GitHub Releases，并按上面的周期持续检查；也可以右键左侧钉子手动选择“检查更新”。v1.1.0 及更早版本仅在启动后检查一次，且没有 API 失败回退。旧版能正常访问 GitHub API 时，重启或手动检查可以发现 v1.1.1；若遇到 API 限流或网络问题，旧版仍可能检查失败或没有自动提示，需要从官方 Releases 手动下载 `PicShot-1.1.1-windows-x64.zip`，退出旧程序后解压运行。新版本无法远程修补已下载的旧程序；升级一次后，后续版本检查才能使用回退和重试机制。程序关闭、设备离线或 GitHub 无法访问时，不能保证收到通知；这不是常驻推送服务，也不收集其他用户的通知送达状态。

下载包会先校验 SHA-256，再由独立脚本关闭旧进程、替换程序文件并重启；`%LocalAppData%\FrameDock\data` 不属于更新包，不会被覆盖。更新会重启程序，尚未另存的内存临时截图不会恢复。
