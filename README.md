# PicShot

PicShot 是一个面向 Windows 的截图与图片工作台。磁盘图片只记录原文件路径，不自动复制图片。

当前正式版本：**v1.1.0**。本次整合单实例运行、微信/QQ 图片目录设置和左侧钉子集中菜单，详见 [完整更新说明](releases/v1.1.0.md)。

下载发布页中的 `PicShot-1.1.0-windows-x64.zip`，解压后运行 `app\PicShot.exe`。设置入口在屏幕最左侧钉子的右键菜单中；右侧袜夹继续用于打开图片收纳，图片自身的右键操作保持不变。

## 未发布的源码更改

- 已移除桌面置顶参考图窗口，改为手动固定在截图绳上。此项尚未包含在 v1.1.0 发布包中。
- 在袜夹或绳上右键图片，选择“固定在绳上”，即可保持悬挂，不再受目录和七天期限限制；手动固定的图片优先显示。点击照片夹也可固定，已经固定时再次点击会取消固定并收回袜夹。
- “收回袜夹”只改变分类，不移动或删除原文件。选择“恢复自动分类”可重新使用原来的目录与七天规则。
- 磁盘图片的手动分类仅作为状态记录保存，重启后恢复，仍只读取原路径、不创建图片副本；原文件不可用时仍不显示。临时截图的内容和分类只保留到程序退出。

## 解决的问题

- 图片可以从任意文件夹导入，不依赖 Windows 的 Screenshots 文件夹。
- 添加文件夹后会持续监听新图片；原文件不可用时，图片会从截图绳上隐藏，原路径恢复后可以重新显示。
- 导入图片、监听文件夹和剪贴板文件列表只引用原文件，不创建本地副本。移动或删除原文件后，PicShot 不会从旧副本继续读取。
- `%LocalAppData%\FrameDock\data\state.json` 保存原文件路径、监听目录等记录，不保存图片内容。原文件仍可访问时，重启后才会恢复显示。
- 程序内截图和剪贴板位图只保存在运行时内存中，不自动写入图片文件；关闭程序后不会恢复。需要长期保留时，请主动使用“保存副本”并选择位置。
- 从绳上右键菜单正常退出会先保存路径记录；若保存失败，会提示并允许取消退出。强制结束进程无法保证本次新增路径记录保存成功。
- 截图绳显示最近 7 天内新出现或更新的截图目录根层图片、下载目录图片，以及本次运行的临时截图；这些图片超过 7 天后自动进入右侧袜夹。截图目录内的子文件夹图片和其他目录的图片不受 7 天等待期限制，直接按原文件夹归入袜夹。绳上图片多时可用鼠标滚轮横向浏览，不因数量多而提前归档。袜夹按原文件夹分类并可搜索、继续浏览，不会移动或复制原图；临时截图即使进入袜夹，关闭程序后仍会消失。截图目录会监听子目录，下载目录由系统定位并监听顶层文件；其他目录可手动添加监听。

## 构建和运行

需要 Windows 10/11 与 .NET Framework 4.8：

```powershell
.\build.ps1
.\build\PicShot.exe
```

仓库现在包含可直接运行的 `build\PicShot.exe` 及其 `.NET Framework 4.8` 配置文件。克隆仓库后可以直接执行 `.\build\PicShot.exe`；修改源码后再执行 `.\build.ps1` 重新生成该文件。其他构建产物、测试截图和本地运行数据不会提交。程序启动后会在屏幕顶部显示一条收起的截图栏。鼠标移到屏幕顶部时展开，鼠标离开后自动收起；单击图片复制，拖拽图片到其他程序取用，点击照片夹可以固定或取消固定在绳上。最右侧的袜夹打开按目录分组的收纳面板，单击图片复制、拖拽取用、右键可固定在绳上或打开原文件。绳上图片右上角的“×”及收纳面板的删除操作都会删除对应原文件（临时截图只移除）；删除原文件前会显示路径并要求确认，失败时保留图片记录。旧版自动创建的副本不再作为原文件的回退来源；旧版剪贴板图片可能以 `library` 内的文件作为原件，仍会按已有路径显示，删除该图片也会删除此文件。旧 `library` 文件不会自动清理，以免误删唯一的图片。从旧版升级时，若状态中仍有副本路径，会先校验并保留 `state.json.legacy` 元数据快照；旧状态有变化时保留带时间戳的新快照。无法完成备份则停止启动，避免覆盖旧路径记录。快照不含图片内容。

### 发布和自动更新

版本号由 `build.ps1 -Version` 注入，默认是 `1.1.0`。发布前更新默认版本、可执行文件和 `releases/<标签>.md` 更新说明，再创建符合 `v1.2.3` 格式的 Git 标签：

```powershell
git tag -a v1.1.0 -m "Release PicShot 1.1.0"
git push origin v1.1.0
```

GitHub Actions 会根据标签构建并发布对应版本的 ZIP，并使用仓库内的中文更新说明。已发布标签不要重复创建或移动。PicShot 会在启动后检查 GitHub Releases，也可以右键左侧钉子手动选择“检查更新”；这不是常驻推送服务，需要能访问 GitHub。下载包会先校验 SHA-256，再由独立脚本关闭旧进程、替换程序文件并重启；`%LocalAppData%\FrameDock\data` 不属于更新包，不会被覆盖。更新会重启程序，尚未另存的内存临时截图不会恢复。
