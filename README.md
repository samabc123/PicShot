# PicShot

PicShot 是一个面向 Windows 的截图与图片工作台。磁盘图片只记录原文件路径，不自动复制图片。

当前正式版本：**v1.1.3**。本次整合双击打开图片、右键菜单外部点击收起，以及手动固定与七天候补规则，详见 [完整更新说明](releases/v1.1.3.md)。

下载发布页中的 `PicShot-1.1.3-windows-x64.zip`，解压后运行 `app\PicShot.exe`。设置入口在屏幕最左侧钉子的右键菜单中，最右侧的收纳篮用于浏览袜夹分类，图片自身的右键操作保持不变。

## 未发布的界面更改

- 按住照片本体或照片夹左右拖动即可调整顺序。照片和夹子沿绳跟随鼠标，旁边的照片滑动让位，松手后归位。将照片本体拖到绳区下方仍可拖入其他应用；单击夹子仍可固定或取消固定。磁盘图片的手动顺序会恢复，不保存图片副本；排序不改变七天期限或候补资格。

- 收纳篮首页采用接近 Windows 11 Fluent 的珍珠灰、雾银与低饱和织物配色。编织篮、针织袜夹、右侧篮子入口和左侧斜钉由 Three.js 三维模型预渲染。透明素材内嵌在 EXE，运行时由原生 WPF 分层组合，不增加浏览器或游戏引擎依赖，也不提供视角旋转。
- 鼠标悬停或键盘聚焦袜夹时轻轻抬起，并在下方显示名称、图片数量与分类来源；长名称可悬停查看全文。点击袜夹或下方箭头进入原有图片列表，返回箭头回到篮子。
- 每篮最多展示 15 个袜夹，更多分类可以翻页，也可继续按名称、图片文件名和原路径搜索。保留创建、重命名、导入、复制、拖拽、双击打开和图片右键功能，不改变分类关系或图片存储方式。
- 为从顶部入口移向中央篮子保留一次短暂过渡时间；正常鼠标浏览仍按离开约 0.8 秒收回。纯键盘操作期间暂不自动收回，移动鼠标或切换窗口后恢复原规则；显示设置改变时重新居中并适应工作区。此处更改只包含在当前源码及仓库内可执行文件中，尚未进入 v1.1.3 正式下载包。

需要修改三维模型时，在 `tools\artwork` 运行 `npm ci` 和 `npm run render`（需要 Node.js 和 Chrome，也可将 `PICSHOT_BROWSER` 设置为 `msedge`）。渲染脚本将透明 PNG 输出到 `src\artwork`，并把检视截图写入 `build\artwork-proof`。普通构建直接使用仓库里的素材，不需要安装 Node.js。

## v1.1.3 更新

- 截图绳按屏幕宽度计算能完整悬挂的一排容量：手动固定优先且不因时间或容量自动收回；自动图片仅使用近七天、符合原目录规则的图片，按新出现或更新时间从新到旧补满剩余位置。超出容量的自动图片在原目录袜夹中候补，绳上图片删除、移走、原文件失效或屏幕容量变化时重新补位；候补图超过七天后，即使有空位也不会自动上绳，仍可手动固定。固定图片本身超过一排容量时保留横向滚动，不把它们自动归档。候补不改写手动分类，不复制、移动或保存图片副本；自建袜夹的显式成员关系保持不变。
- 右击图片后，点击软件外部区域会关闭菜单，并将截图绳和收纳篮一起收回；选择菜单命令不视作外部取消，仍保留原有操作和收起动画。
- 绳上和篮子内的图片支持双击打开；单击仍复制，拖拽仍取用。磁盘图片由系统默认看图程序打开；临时截图直接使用内存预览，不自动保存文件，关闭预览不会删除图片记录。内存预览是普通看图窗口，不是桌面置顶功能。

## v1.1.2 更新

- 收纳篮：绳子最右侧改为装有袜子的篮子。打开后先展示放大的命名袜子，每只袜子对应一个自建袜夹或原目录分类；点击袜子查看图片，点击返回箭头回到篮子。右上角加号可创建袜夹，新袜夹会加入篮子。首页支持按袜夹名称、图片文件名和原路径搜索；长名称悬停可查看全文。所有图案内置于程序，不需要额外下载素材。
- 自建袜夹：打开右侧篮子，点击右上角加号创建分类，再选择“导入图片”。支持重命名、同一图片加入多个袜夹，以及从当前袜夹移出。删除袜夹仅删除分类，不删除图片记录或原文件；图片右键“删除原文件”仍是单独的确认操作。名称、原图路径和分类关系保存后可在重启恢复，不复制、移动或上传原图。新导入的图片直接归档，已有图片保留其绳上分类。原文件移动或删除后，自建袜夹保留不可用记录，不读取旧副本；恢复原路径后可重新显示。临时截图需先主动另存后再导入。
- 隐私边界：自建袜夹是本地分类，不是加密保险箱，不提供密码或访问隔离。导入证件照片前，请保护原文件及 Windows 账户；分类名称和原图路径以普通状态元数据保存。测试与代码提交不包含用户照片或个人分类。
- 稳定性修复：透明常驻窗口不再主动抢焦点，Alt+F4 不会关闭截图绳，仍可通过钉子菜单明确退出。右键菜单统一使用 WPF，并在隐藏、替换菜单和退出时清理；文件移动、删除、暂时无法读取及设置保存失败不会直接打断常驻流程。显示布局改变后重新定位截图绳。临时图片的估算像素内存上限为 512 MiB，达到上限时提示并停止继续收集，不自动删除已有图片，也不转存到磁盘。启动、退出及异常诊断写入 `%LocalAppData%\FrameDock\data\logs\runtime.log`，自动轮换，仅保存两份有界文本日志；可能包含异常中的本地路径，不含截图像素，不自动上传。不掩盖未知异常，也不宣称已定位所有退出原因。
- 更新交接失败时恢复“稍后”和重试操作；交接前先确认路径记录保存成功，避免安装程序已启动后又因重复保存而取消退出。仅明确选择安装更新才会执行交接，不自动重启。
- 展开截图绳后，左上角钉子下方显示当前运行程序的版本号（例如 `v1.1.2`），收起时随绳索隐藏。版本号读取程序自身版本，不代表最新发布版本，也不改变更新检测规则。
- 修复点击截图后选区窗口变黑：先获取当前屏幕的内存快照，再显示选区遮罩，并从未叠加遮罩的快照裁剪原图，不把遮罩和选区边框截入结果。选区坐标按实际画布与像素尺寸换算，支持反向拖选及边缘裁剪；Esc 或右键可取消。截图失败会提示并恢复截图绳，不自动将快照保存到磁盘。
- 修复一次截屏出现两张记录：优先读取剪贴板原始 PNG，按像素内容关联 30 秒内的自动收集记录，重复通知不延长关联窗口；剪贴板位图与新发现的原文件一致时，仅保留原文件路径，并沿用临时图片的手动分类。不合并两个不同路径的文件，不用手动导入覆盖临时记录，也不拦截用户主动进行的多次程序内截图；只在内存中计算指纹，不保存图片副本。像素或透明度不一致时保守保留，不使用模糊匹配。

## 解决的问题

- 图片可以从任意文件夹导入，不依赖 Windows 的 Screenshots 文件夹。
- 添加文件夹后会持续监听新图片；原文件不可用时，图片会从截图绳上隐藏，原路径恢复后可以重新显示。
- 导入图片、监听文件夹和剪贴板文件列表只引用原文件，不创建本地副本。移动或删除原文件后，PicShot 不会从旧副本继续读取。
- `%LocalAppData%\FrameDock\data\state.json` 保存原文件路径、监听目录等记录，不保存图片内容。原文件仍可访问时，重启后才会恢复显示。
- 程序内截图和剪贴板位图只保存在运行时内存中，不自动写入图片文件；关闭程序后不会恢复。需要长期保留时，请主动使用“保存副本”并选择位置。
- 从左侧钉子右键菜单正常退出会先保存路径记录；若保存失败，会提示并允许取消退出。强制结束进程无法保证本次新增路径记录保存成功。
- 截图绳自动选择最近 7 天内新出现或更新的截图目录根层图片、下载目录图片，以及本次运行的临时截图；超过 7 天后不再自动悬挂。截图目录内的子文件夹图片和其他目录的图片直接按原文件夹归入袜夹。按一排容量显示，超量自动图片在袜夹候补、空位自动补入，手动固定不受七天及自动容量限制；固定图片本身超量时可以横向浏览，自动图片继续候补。袜夹按原文件夹分类并可搜索、继续浏览，不会移动或复制原图；临时截图即使进入袜夹，关闭程序后仍会消失，手动固定也不会使内存截图在重启后恢复。截图目录会监听子目录，下载目录由系统定位并监听顶层文件；其他目录可手动添加监听。

## 构建和运行

需要 Windows 10/11 与 .NET Framework 4.8：

```powershell
.\build.ps1
.\build\PicShot.exe
```

仓库现在包含可直接运行的 `build\PicShot.exe` 及其 `.NET Framework 4.8` 配置文件。克隆仓库后可以直接执行 `.\build\PicShot.exe`；修改源码后再执行 `.\build.ps1` 重新生成该文件。其他构建产物、测试截图和本地运行数据不会提交。程序启动后会在屏幕顶部显示一条收起的截图栏。鼠标移到屏幕顶部时展开，鼠标离开后自动收起；单击图片复制，拖拽图片到其他程序取用，点击照片夹可以固定或取消固定在绳上。最右侧的篮子打开命名袜子分类页，点击袜子进入图片列表，单击图片复制、拖拽取用、右键可固定在绳上或打开原文件。绳上图片右上角的“×”及收纳面板的删除操作都会删除对应原文件（临时截图只移除）；删除原文件前会显示路径并要求确认，失败时保留图片记录。旧版自动创建的副本不再作为原文件的回退来源；旧版剪贴板图片可能以 `library` 内的文件作为原件，仍会按已有路径显示，删除该图片也会删除此文件。旧 `library` 文件不会自动清理，以免误删唯一的图片。从旧版升级时，若状态中仍有副本路径，会先校验并保留 `state.json.legacy` 元数据快照；旧状态有变化时保留带时间戳的新快照。无法完成备份则停止启动，避免覆盖旧路径记录。快照不含图片内容。

### 发布和自动更新

版本号由 `build.ps1 -Version` 注入，默认是 `1.1.3`。发布前更新默认版本、可执行文件和 `releases/<标签>.md` 更新说明，再创建符合 `v1.2.3` 格式的 Git 标签：

```powershell
$version = '1.1.4' # 示例：仅在准备发布该版本时使用
git tag -a "v$version" -m "Release PicShot $version"
git push origin "v$version"
```

GitHub Actions 会根据标签构建并发布对应版本的 ZIP，并使用仓库内的中文更新说明。上面的标签命令仅展示格式；下一次发布必须使用比现有正式版本更高的新版本号，并同步更新版本、说明文件和标签，不能重复创建或移动已发布标签。普通 `git push` 只更新源码，不生成新正式版本，也不会让旧客户端收到更新通知。

v1.1.1 及之后版本会在启动后约 5 秒首次检查 GitHub Releases，并按上面的周期持续检查；也可以右键左侧钉子手动选择“检查更新”。v1.1.0 及更早版本仅在启动后检查一次，且没有 API 失败回退。旧版能正常访问 GitHub API 时，重启或手动检查可以发现 v1.1.3；若遇到 API 限流或网络问题，旧版仍可能检查失败或没有自动提示，需要从官方 Releases 手动下载 `PicShot-1.1.3-windows-x64.zip`，退出旧程序后解压运行。新版本无法远程修补已下载的旧程序；升级一次后，后续版本检查才能使用回退和重试机制。程序关闭、设备离线或 GitHub 无法访问时，不能保证收到通知；这不是常驻推送服务，也不收集其他用户的通知送达状态。

下载包会先校验 SHA-256，再由独立脚本关闭旧进程、替换程序文件并重启；`%LocalAppData%\FrameDock\data` 不属于更新包，不会被覆盖。更新会重启程序，尚未另存的内存临时截图不会恢复。
